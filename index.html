AIDevWorkflow

تطوير منظّم بمساعدة الذكاء الاصطناعي — من المتطلبات حتى الإصدار.

مهارة (Skill) تضيفها إلى أداة AI التي تستخدمها للبرمجة. تبدأ فقط عندما تستدعيها، وتنقل طلبك إلى نتيجة مختبَرة ومراجَعة بعد موافقتك على المواصفات والخطة. تُحفظ الخطوات في ملفات داخل مشروعك لتتابعها لاحقًا أنت أو أداة AI أخرى.

ابدأ بسرعة

هذا هو المسار المختصر لتشغيل أول مهمة. التثبيت مرة واحدة على جهازك، ثم تعمل المهارة داخل مشروعك.

التفاصيل وخيارات التثبيت

  1. ثبّت المهارة

    تحتاج git وPython 3.9 أو أحدث. من مجلد تريد حفظ نسخة المهارة فيه، نفّذ الأوامر التالية في Terminal أو PowerShell. على Windows اكتب python بدل python3:

    سطر الأوامر
    git clone https://github.com/ahmedzein-dev/ai-dev-workflow.git
cd ai-dev-workflow
python3 skills/ai-dev-workflow/scripts/install.py
python3 skills/ai-dev-workflow/scripts/install.py doctor

    إذا انتهى الفحص بعبارة No problems found.، أغلق أداة AI وافتحها من جديد.

  2. افتح مشروعك وابدأ المهمة

    افتح مجلد مشروعك، وهو مستودع git، في أداة AI. اكتب طلبك في المحادثة باسم المهارة؛ اختر الصيغة التي تناسب أداتك:

    Claude Code، Gemini CLI، Antigravity
    /ai-dev-workflow أضف المفضلة إلى قائمة المنتجات
    Codex
    $ai-dev-workflow أضف المفضلة إلى قائمة المنتجات

    استبدل طلب المفضلة بطلبك أنت.

  3. أكّد الإعداد ثم وافق

    في أول مهمة فقط، اختر قالب المواصفات وفحوص مشروعك وطريقة حفظ السجلات عندما يسألك AI. بعد ذلك يعرض المواصفات، ثم الخطة. اقرأ كل واحدة واكتب الموافقة المناسبة في وقتها إن كانت صحيحة:

    ردّان منفصلان:أوافق على المواصفاتأوافق على الخطة

    بعد الموافقتين، ينفّذ AI التغيير ويشغّل الفحوص ويعطيك تقريرًا بالنتيجة.

مثبّتة بالفعل؟ ابدأ من الخطوة 2. ولشرح كل قرار ومكان الملفات، راجع خطوات المهمة الكاملة.

يقوم به مساعد AI وحده. أنت تنتظر فقط.

ثبّت المهارة

اختر طريقة واحدة: ثبّتها على جهازك لتستخدمها في كل مشاريعك (الخطوات التالية)، أو داخل مشروع واحد إذا أردت أن تصل نسخة منها إلى زملائك وبيئات العمل السحابية.

  1. سطر الأوامر

    افتح تطبيق سطر الأوامر وتأكّد من وجود git و Python

    تحتاج إلى git، وإلى Python 3.9 أو أحدث. اكتب:

    سطر الأوامر
    git --version
python3 --version

    يجب أن يظهر رقم إصدار لكل منهما، مثل Python 3.12.4.

    على Windows: اكتب python بدلًا من python3 في كل أوامر هذه الصفحة.

  2. سطر الأوامر

    نزّل AIDevWorkflow

    نفّذ هذا في أي مجلد خارج مشاريعك، مثل مجلد المستخدم:

    سطر الأوامر
    git clone https://github.com/ahmedzein-dev/ai-dev-workflow.git
cd ai-dev-workflow

    احتفظ بهذا المجلد؛ ستحتاجه للتحديث ولإلغاء التثبيت.

  3. سطر الأوامر

    ثبّت المهارة

    سطر الأوامر
    python3 skills/ai-dev-workflow/scripts/install.py

    يضع المثبّت نسخة واحدة في ~/.agents/skills يقرؤها Codex و Gemini CLI مباشرة، ويربط بها Claude Code، و Antigravity إن كان مثبّتًا.

  4. سطر الأوامر

    تحقّق من التثبيت

    سطر الأوامر
    python3 skills/ai-dev-workflow/scripts/install.py doctor

    آخر سطر في النتيجة الصحيحة: No problems found.

  5. أنت

    أعد تشغيل مساعد AI

    أغلق مساعد AI ثم افتحه من جديد حتى يتعرّف على المهارة.

بديل التثبيت على الجهاز: ثبّتها داخل مشروع واحد للفريق أو للسحابة

استخدم هذه الطريقة إذا كان مساعد AI يعمل في نسخة من مشروعك على جهاز زميل أو في السحابة ولا يرى المهارات المثبّتة على جهازك. يجب أن يكون المشروع مستودع git. نزّل AIDevWorkflow كما في الخطوة 2، ثم نفّذ الأمر التالي من داخل مجلده:

سطر الأوامر
python3 skills/ai-dev-workflow/scripts/install.py install --project ../my-app
python3 skills/ai-dev-workflow/scripts/install.py doctor --project ../my-app

../my-app مثال لمشروع اسمه my-app بجانب مجلد ai-dev-workflow. استبدله بمسار مجلد مشروعك الفعلي؛ إذا كان في مكان آخر، اكتب مساره الكامل بين علامتي اقتباس. ينسخ المثبّت المهارة إلى .agents/skills/ai-dev-workflow و .claude/skills/ai-dev-workflow داخل المشروع. احفظ المجلدين في git وارفعهما مع مشروعك حتى يراهما الفريق ومساعدو AI في السحابة.

إذا ظهرت المهارة مرتين داخل هذا المشروع، فهناك نسخة مثبّتة على جهازك وأخرى داخل المشروع. اختر طريقة واحدة لهذا المشروع؛ يفحص أمر doctor النسخ المكرّرة.

اختياري: استخدم نموذج مواصفات من إعدادك

ملف القالب مستند .md فيه عناوين المواصفات وحقول تملؤها لاحقًا لكل مهمة؛ لا تضع فيه تفاصيل مهمة محددة. افتح examples/templates/example-spec-template.md واحفظ نسخة منه في مجلد خاص خارج أي مستودع، مثل ../my-templates/spec.md، ثم عدّل العناوين بما يناسبك.

من داخل مجلد ai-dev-workflow، أضف الملف إلى مكتبتك الخاصة بهذا الأمر. my-template اسم تختاره للقالب، و../my-templates/spec.md مكان الملف الذي أنشأته، بالنسبة إلى المجلد الذي تعمل منه:

سطر الأوامر
python3 skills/ai-dev-workflow/scripts/install.py add-template my-template ../my-templates/spec.md

ملف القواعد اختياري. هو ملف .json يحدد ما الذي يفحصه المحرك في المواصفات، مثل الأقسام المطلوبة وصيغة معايير القبول. إذا أردت قواعد خاصة، احفظ نسخة من examples/templates/example-spec-template.rules.json في ../my-templates/spec.rules.json وعدّلها لتطابق عناوين قالبك. عندها استخدم الأمر التالي بدلًا من الأمر السابق:

سطر الأوامر — مع ملف قواعد
python3 skills/ai-dev-workflow/scripts/install.py add-template my-template ../my-templates/spec.md --rules ../my-templates/spec.rules.json

نفّذ واحدًا فقط من الأمرين. بدون ملف قواعد إضافي، يراجع المحرك بنية القالب والحقول غير المعبأة.

المثبّت يحتفظ بنسخة من القالب والقواعد في مكتبتك الخاصة خارج المشاريع. عند إعداد مشروع، تختار القالب بالاسم user:my-template. وإن لم تضف قالبًا، يستخدم مساعد AI قالبًا موجودًا في المشروع أو يطلبه منك؛ لا ينشئ قالبًا من عنده.

تشغيل مهمة

من طلبك حتى نتيجة مراجَعة. دورك في الخطوات التي عليها علامة «أنت».

  1. سطر الأوامر

    افتح مساعد AI داخل مشروعك

    انتقل إلى مجلد مشروعك، ثم شغّل مساعد AI. ../my-app مثال؛ استبدله بمسار مشروعك كما في خطوة التثبيت:

    سطر الأوامر
    cd ../my-app
claude

    اكتب codex أو gemini بدلًا من claude حسب مساعد AI الذي تستخدمه. وإن كنت تستخدم تطبيقًا على سطح المكتب (مثل Claude أو Codex أو Antigravity)، فافتح مجلد المشروع في التطبيق بدلًا من ذلك.

    يجب أن يكون المشروع مستودع git.

  2. محادثة مساعد AI

    ابدأ المهمة

    اكتب اسم المهارة ثم طلبك. ضع طلبك أنت مكان المثال، بالعربية أو بالإنجليزية:

    Claude Code، Gemini CLI، Antigravity
    /ai-dev-workflow أضف المفضلة إلى قائمة المنتجات
    Codex
    $ai-dev-workflow أضف المفضلة إلى قائمة المنتجات

    الطلب العادي من دون اسم المهارة لا يبدأ سير العمل.

  3. أنتمحادثة مساعد AI

    أول مرة في المشروع فقط: أكّد الإعداد

    يعرض مساعد AI ما وجده في مشروعك، ويسألك عن:

    • ملفات التعليمات التي يلتزم بها كل مساعد AI، مثل CLAUDE.md أو AGENTS.md.
    • قالب المواصفات الذي يُستخدم.
    • الفحوص التي تُشغَّل، مثل الاختبارات وأداة التحليل.
    • هل تُحفظ سجلات المهام في git؟
      • all — كل السجلات.
      • config-only — الإعدادات فقط، وتبقى المهام على جهازك.
      • none — لا شيء، وتبقى كل السجلات على جهازك.

    تجيب مرة واحدة فقط لكل مشروع.

  4. تلقائيأنت

    الاستكشاف: أجب عن أسئلة مساعد AI

    يقرأ مساعد AI الكود أولًا، ثم يسأل فقط عمّا لا يجيب عنه الكود. أجب باختصار في المحادثة.

  5. أنتمحادثة مساعد AI

    إن نقصت تفاصيل من الواجهة البرمجية: أرسل الرسالة

    يكتب مساعد AI رسالة جاهزة لمطوّر الواجهة الخلفية (Backend) ويتوقف. أرسلها له بالطريقة المعتادة (بريد، Slack…)، ثم الصق رده في المحادثة.

  6. أنتمحادثة مساعد AIبوابة موافقة

    وافق على المواصفات

    اقرأ المواصفات التي يعرضها مساعد AI. إن كانت صحيحة، اكتب:

    ردّك:أوافق على المواصفات

    وإن أردت تغيير شيء، اكتب ما تريد تغييره. الأسئلة أو عبارة «جيد، لكن…» لا تُعدّ موافقة.

  7. أنتمحادثة مساعد AIبوابة موافقة

    وافق على الخطة

    اقرأ خطة التنفيذ. إن كانت صحيحة، اكتب:

    ردّك:أوافق على الخطة
  8. تلقائي

    التنفيذ والاختبار والإصلاح والمراجعة

    يعدّل مساعد AI الكود خطوة بخطوة حسب الخطة، ويشغّل فحوص المشروع، ويصلح ما يفشل، ثم يراجع النتيجة. أنت تنتظر فقط.

    قد يطلب مساعد AI إذنك لتشغيل أمر أو تعديل ملف؛ هذا من إعدادات مساعد AI نفسه.

  9. أنت

    اقرأ التقرير النهائي

    ملخص قصير: ما الذي نُفّذ، وما الذي اختُبر، وما الذي بقي مفتوحًا. والحالة فيه لا تتجاوز أبدًا ما تثبته الأدلة.

تغيير صغير؟ اكتب في المحادثة استخدم المسار السريع. يعرض مساعد AI المواصفات والخطة معًا، فتوافق عليهما في رسالة واحدة: أوافق على المواصفات والخطة

موافقتك وقواعد الأمان

  • كلماتك وحدها هي الموافقة.يسجّل مساعد AI ردك كما كتبته، مثل «أوافق على المواصفات»، ولا يوافق نيابة عنك أبدًا.
  • ما توافق عليه يُجمَّد.تُحفظ كل نسخة وافقت عليها للقراءة فقط مع بصمة رقمية. وإن تغيّر المستند بعد ذلك، يحتاج موافقتك من جديد.
  • لا كود قبل الموافقة على الخطة في المهمة النشطة.في Claude Code يمنع خطّاف (hook) التعديل المبكر للكود. أما أدوات AI الأخرى فتلتزم بالقاعدة، والمحرك يكشف الملفات التي تغيّرت قبل الموافقة.
  • فحص قبل كل جلسة تعديل داخل سير العمل.عند بدء جلسة جديدة، أو تبديل مساعد AI، أو استئناف مهمة، يعيد مساعد AI التحقق من الموافقات قبل تعديل الكود ضمن المهمة النشطة.
  • إذا طلبت أنت تخطي مرحلة.يذكر مساعد AI المراحل التي طلبت تخطيها ويسجّل طلبك وسبب الإيقاف المؤقت، ثم ينفّذ طلبك خارج المهمة النشطة. تظل المراحل المتخطاة غير مكتملة، ولا تُسجَّل موافقة لم تمنحها أو نتيجة لم تُختبَر. لا يقرر مساعد AI تخطي أي مرحلة من تلقاء نفسه.
  • لا أسرار في السجلات.كلمات المرور والرموز والمفاتيح لا تُحفظ أبدًا في ملفات المهمة.

عندما تنقص معلومة

يحدد مساعد AI ما تحتاجه هذه المهمة فقط، ويصنّف كل عنصر:

مانع (Blocking)
مطلوب قبل أن تكتمل مرحلة: المواصفات أو الخطة أو التنفيذ أو الإنهاء.
غير مانع (Non-blocking)
مفيد، لكنه ليس ضروريًا.
مؤكَّد (Verified)
تم التحقق منه بدليل موثوق.
غير منطبق (Not applicable)
لا علاقة له بهذه المهمة.

عندما يتوقف العمل بسبب عنصر مانع، تبدأ رسالة الحالة بسطر مثل هذا (معناه: متوقف بانتظار عقد الواجهة البرمجية):

BLOCKED — Awaiting backend API contract

وعندما تنقص تفاصيل الواجهة البرمجية، يكتب مساعد AI رسالة ترسلها كما هي، مثل:

مرحبًا! نضيف ميزة المفضلة إلى التطبيق: يضغط المستخدم المسجَّل على رمز القلب ليحفظ منتجًا، ويرى المنتجات المحفوظة في شاشة المفضلة. لإكمال المواصفات نحتاج إلى: 1. ما الواجهات (endpoints) الخاصة بالحفظ والحذف وعرض القائمة؟ 2. هل القائمة مقسّمة إلى صفحات، وكيف تُرتَّب؟ 3. ماذا تُرجع الواجهة إذا لم يعد المنتج موجودًا؟ هل يمكنك مشاركة مثال لطلب واستجابة؟ شكرًا!

الاختبار والمراجعة والحالة النهائية

  • أدلة حقيقية.يشغّل المحرك كل فحص ويسجّل نتيجته مع بصمة للكود. وإن تغيّر الكود بعد ذلك، تصبح النتيجة قديمة ويجب تشغيل الفحص من جديد.
  • المشكلات القديمة منفصلة.المشكلات الموجودة قبل المهمة تُعرض منفصلة عن المشكلات الجديدة.
  • الفحص الذي لم يعمل لا يُعدّ ناجحًا أبدًا.يُسجَّل «متوقفًا» مع ذكر السبب.
  • مراجعة مستقلة.يراجع العمل مساعد AI آخر أو جلسة منفصلة كلما أمكن، وإلا يذكر التقرير أنها مراجعة ثانية من مساعد AI نفسه.

AIDevWorkflow

Structured AI-Assisted Development — From Requirements to Release.

A skill for your AI coding tool. It runs only when you call it, taking your request to a tested, reviewed result after you approve the spec and plan. Each step is saved in your project so you or another AI tool can continue later.

Quick Start

The shortest path to your first task: install once on your computer, then use the skill inside your project.

Installation details and options

  1. Install the skill

    You need git and Python 3.9 or newer. From a folder where you want to keep the skill, run these commands in Terminal or PowerShell. On Windows, use python instead of python3:

    Terminal / PowerShell
    git clone https://github.com/ahmedzein-dev/ai-dev-workflow.git
cd ai-dev-workflow
python3 skills/ai-dev-workflow/scripts/install.py
python3 skills/ai-dev-workflow/scripts/install.py doctor

    If the check ends with No problems found., close and reopen your AI tool.

  2. Open your project and start a task

    Open your project folder, which must be a git repository, in your AI tool. Type your request in its chat with the skill name. Use the form for your tool:

    Claude Code, Gemini CLI, Antigravity
    /ai-dev-workflow Add favorites to the product list
    Codex
    $ai-dev-workflow Add favorites to the product list

    Replace the favorites example with your own request.

  3. Confirm setup, then approve

    On the first task in a project, choose the spec template, project checks and how to save records when the AI tool asks. It then shows the spec, followed by the plan. Read each and send the matching approval when it appears, if it is right:

    Two separate replies:approve the specapprove the plan

    After both approvals, the AI tool makes the change, runs the checks and reports the result.

Already installed? Start at step 2. For each decision and saved file, read the full task walkthrough.

Install the skill

Choose one method: install it on your computer for all projects (the steps below), or inside one project so teammates and cloud environments receive a copy.

  1. Terminal

    Open Terminal and check git and Python

    Terminal
    git --version
python3 --version

    Each should print a version number, such as Python 3.12.4.

    On Windows, type python instead of python3 in every command on this page.

  2. Terminal

    Download AIDevWorkflow

    Run this in any folder outside your projects, such as your home folder:

    Terminal

    Keep this folder: you will use it to update and to uninstall.

  3. Terminal

    Install the skill

    Terminal
    python3 skills/ai-dev-workflow/scripts/install.py

    The installer puts one copy in ~/.agents/skills, which Codex and Gemini CLI read directly, and links Claude Code to it — and Antigravity, if it is installed.

  4. Terminal

    Check the installation

    Terminal
    python3 skills/ai-dev-workflow/scripts/install.py doctor

    The last line should be: No problems found.

  5. You

    Restart your agent

    Close your agent and open it again, so it finds the skill.

Instead of a computer install: add the skill to one project

Choose this when a teammate or cloud AI tool only sees a checkout of your project. The project must be a git repository. Download AIDevWorkflow as in step 2, then run these commands from its folder:

Terminal / PowerShell
python3 skills/ai-dev-workflow/scripts/install.py install --project ../my-app
python3 skills/ai-dev-workflow/scripts/install.py doctor --project ../my-app

../my-app means a project named my-app next to your ai-dev-workflow folder. Replace it with your project's actual path; use a quoted full path if the project is elsewhere. The installer copies the skill into .agents/skills/ai-dev-workflow and .claude/skills/ai-dev-workflow inside that project. Commit and push both folders with the project so teammates and cloud AI tools can use them.

If the skill appears twice in this project, there is a computer copy and a project copy. Use one method for this project; doctor checks for duplicates.

Optional: use your own specification template

The template file is a .md document with specification headings and fields to fill in for each task, rather than details of one task. Open examples/templates/example-spec-template.md, save a copy outside any repository, such as ../my-templates/spec.md, and adapt it.

From the ai-dev-workflow folder, add that file to your private library. my-template is the name you choose; ../my-templates/spec.md is the file's location relative to this folder:

Terminal / PowerShell
python3 skills/ai-dev-workflow/scripts/install.py add-template my-template ../my-templates/spec.md

The rules file is optional. It is a .json file that tells the engine what to check in a specification, such as required sections and the format of acceptance criteria. To add rules, save a copy of examples/templates/example-spec-template.rules.json at ../my-templates/spec.rules.json and edit it to match your template headings. Then run this command instead of the one above:

Terminal / PowerShell — with rules
python3 skills/ai-dev-workflow/scripts/install.py add-template my-template ../my-templates/spec.md --rules ../my-templates/spec.rules.json

Run only one of the two commands. Without an extra rules file, the engine still checks the template structure and unfilled fields.

The installer keeps copies of the template and rules in your private library outside your projects. During project setup, choose it by the name user:my-template. Without a custom template, the AI tool uses one already in the project or asks you for one; it never invents one.

Your approval and the safety rules

  • Only your words approve.The agent records your reply as you wrote it, such as "approve the spec". It never approves on your behalf.
  • What you approve is frozen.Each version you approve is saved read-only with a fingerprint. If the document changes later, it needs your approval again.
  • No code before an approved plan in an active task.In Claude Code, a hook blocks early code edits. Other agents follow the rule, and the engine reports files changed before approval.
  • A check before every editing session in the workflow.When a new session starts, the agent changes or a task resumes, the agent re-checks approvals before editing code under the active task.
  • If you explicitly ask to skip a stage.The agent names the skipped stages, records your request and the reason for pausing, then follows your instruction outside the active task. Skipped stages remain incomplete; no approval or test result is invented. The agent never decides to skip a stage on its own.
  • No secrets in records.Passwords, tokens and keys are never saved in task files.

When information is missing

The agent lists only what this task needs, and gives each item a class:

Blocking
Needed before a stage can finish: the spec, the plan, the implementation or completion.
Non-blocking
Helpful, not essential.
Verified
Confirmed with reliable evidence.
Not applicable
Not relevant to this task.

While a blocking item stops the work, the status message starts with a line like this:

BLOCKED — Awaiting backend API contract

For a missing API detail, the agent writes a message you can send as it is, for example:

Hi! We're adding saved favorites to the app: a signed-in user taps a heart to save an item and sees saved items on a favorites screen. To finish the spec we need: 1. Which endpoints save, remove and list favorites? 2. Is the list paginated, and how is it sorted? 3. What does the API return when the item no longer exists? Could you share an example request and response? Thanks!

Testing, audit and the final status

  • Real evidence.The engine runs each check and records its result with a fingerprint of the code. If the code changes later, the result is out of date and the check must run again.
  • Old problems stay separate.Problems that existed before the task are reported separately from new ones.
  • A check that did not run is never "passed".It is recorded as blocked, with the reason.
  • Independent review.Another agent or a separate session reviews the work when possible; otherwise the report says it was a second pass by the same agent.

The final status

StatusMeaning
CompletedEverything passed with evidence; no unresolved Critical or Important finding.
Completed with LimitationsNothing failed, but some items could not be verified, or you accepted an Important finding.
Partially CompletedSomething failed, steps remain, or a Critical finding remains, even if you accepted it.
BlockedWork cannot continue until someone provides what is missing.

Accepting a known Critical or Important finding never gives "Completed".

The task files

Everything is inside the .ai-dev-workflow folder in your project:

config.json
Project setup: instruction files, template, checks.
templates/
The project's spec template.
tasks/saved-favorites/
One folder per task, containing:
spec.md
The spec.
dependencies.md
What the task needed from outside, with messages and replies.
plan.md
The implementation plan, frozen once approved.
approved/
Read-only copies of every version you approved.
state.json
Stage, approvals and progress; only the engine writes it.
verification.md
The checks and their results.
audit.md
Review findings.
report.md
The final report.

Whether these files go into git is your choice per project: all, config-only or none.

Questions, updating and uninstalling

Why doesn't the skill start by itself?

So that your normal requests stay normal. You decide when a task goes through the workflow.

Can I use my own spec template?

Yes. Each project uses the template you choose during setup. Rules you mark as mandatory block approval until they are met; recommendations only warn. There is no limit on how many requirements a spec has.

Does it need an internet connection?

The skill itself works offline. Your agent needs its usual connection.

Does it change anything in my project besides .ai-dev-workflow?

Only the code changes in plans you approved. Instruction files such as CLAUDE.md are never edited. Depending on how you chose to save records, a line may be added to .git/info/exclude.

Update to a newer version

From the folder where you downloaded ai-dev-workflow during setup, run these commands. Skip cd if you are already inside it:

Terminal
cd ai-dev-workflow
git pull
python3 skills/ai-dev-workflow/scripts/install.py update
Uninstall

From the folder where you downloaded ai-dev-workflow during setup, first see what would be removed. Skip cd if you are already inside it:

Terminal
cd ai-dev-workflow
python3 skills/ai-dev-workflow/scripts/install.py uninstall

Then remove it:

Terminal
python3 skills/ai-dev-workflow/scripts/install.py uninstall --yes

Task files in your projects are never touched.
