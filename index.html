AIDevWorkflow

تطوير منظّم بمساعدة الـ AI، من المتطلبات لحد الـ release.

مهارة (Skill) بتضيفها لأداة الـ AI اللي بتبرمج بيها. مابتشتغلش غير لما إنت تناديها، وبتاخد طلبك لحد نتيجة متجرّبة ومتراجعة، بعد ما توافق على المواصفات والخطة. وكل خطوة بتتحفظ في ملفات جوه مشروعك، عشان تكمّل بعدين، إنت أو أداة AI تانية.

ابدأ بسرعة

ده أقصر طريق لأول مهمة. بتثبّت مرة واحدة على جهازك، وبعدين المهارة بتشتغل جوه مشروعك.

التفاصيل وطرق التثبيت

  1. ثبّت المهارة

    محتاج git وPython 3.9 أو أحدث. افتح Terminal (أو PowerShell على Windows) وشغّل الأوامر دي زي ما هي. هيتنزل فولدر اسمه ai-dev-workflow في المكان اللي سطر الأوامر فاتح فيه دلوقتي، وده عادةً فولدر المستخدم. ماتشغّلهاش جوه فولدر مشروعك: الفولدر ده أداة لجهازك كله، ولو اتنزل جوه المشروع ممكن يتضاف لـ git بتاع المشروع بالغلط. (لو عايز المهارة جوه مشروع معيّن، استخدم التثبيت جوه مشروع.) وخلّي الفولدر ده عندك، لأنك هتحتاجه للتحديث. على Windows اكتب python بدل python3:

    سطر الأوامر
    git clone https://github.com/ahmedzein-dev/ai-dev-workflow.git
cd ai-dev-workflow
python3 skills/ai-dev-workflow/scripts/install.py
python3 skills/ai-dev-workflow/scripts/install.py doctor

    لو الفحص خلص بجملة No problems found.، اقفل أداة الـ AI وافتحها تاني.

  2. افتح مشروعك وابدأ المهمة

    افتح فولدر مشروعك في أداة الـ AI، ولازم يكون ريبو git. اكتب طلبك في الشات ومعاه اسم المهارة، بالشكل اللي يناسب أداتك:

    Claude Code، Gemini CLI، Antigravity
    /ai-dev-workflow ضيف المفضلة لقايمة المنتجات
    Codex
    $ai-dev-workflow ضيف المفضلة لقايمة المنتجات

    حط طلبك إنت مكان طلب المفضلة.

  3. أكّد الإعداد ووافق

    في أول مهمة بس، الـ AI بيقترح قالب المواصفات، والفحوص بتاعة مشروعك، وطريقة حفظ السجلات، وبيشرح كل اقتراح. وافق عليها زي ما هي، أو غيّر اللي إنت عايزه. بعدها بيعرض المواصفات، وبعدين الخطة. اقرا كل واحدة، ولو صح، اكتب الموافقة بتاعتها في وقتها:

    ردّين منفصلين:موافق على المواصفاتموافق على الخطة

    بعد الموافقتين، الـ AI بينفّذ التغيير، ويشغّل الفحوص، ويديك تقرير بالنتيجة.

مثبّتها قبل كده؟ ابدأ من الخطوة 2. ولو عايز تعرف كل قرار والملفات فين، شوف خطوات المهمة كاملة.

ثبّت المهارة

اختار طريقة واحدة: ثبّتها على جهازك عشان تستخدمها في كل مشاريعك (الخطوات اللي تحت)، أو جوه مشروع واحد لو عايز نسخة منها توصل لزمايلك ولبيئات الشغل على الـ cloud.

  1. سطر الأوامر

    افتح سطر الأوامر واتأكد إن git وPython موجودين

    محتاج git، وPython 3.9 أو أحدث. اكتب:

    سطر الأوامر
    git --version
python3 --version

    لازم يظهر رقم نسخة لكل واحد، زي Python 3.12.4.

    على Windows: اكتب python بدل python3 في كل أوامر الصفحة دي.

  2. سطر الأوامر

    نزّل AIDevWorkflow

    شغّل ده برّه فولدر مشروعك، مثلاً في فولدر المستخدم (المكان اللي سطر الأوامر بيفتح فيه عادةً). هيتنزل هناك فولدر اسمه ai-dev-workflow:

    سطر الأوامر
    git clone https://github.com/ahmedzein-dev/ai-dev-workflow.git
cd ai-dev-workflow

    خلّي الفولدر ده عندك، هتحتاجه للتحديث ولإلغاء التثبيت.

  3. سطر الأوامر

    ثبّت المهارة

    سطر الأوامر
    python3 skills/ai-dev-workflow/scripts/install.py

    المثبّت بيحط نسخة واحدة في ~/.agents/skills. Codex وGemini CLI بيقروها من هناك على طول، وبيربطها بـ Claude Code، وبـ Antigravity لو متثبّت.

  4. سطر الأوامر

    اتأكد إن التثبيت تمام

    سطر الأوامر
    python3 skills/ai-dev-workflow/scripts/install.py doctor

    لو كله تمام، آخر سطر هيبقى: No problems found.

  5. أنت

    شغّل مساعد الـ AI من جديد

    اقفل مساعد الـ AI وافتحه تاني، عشان يشوف المهارة.

بدل التثبيت على الجهاز: ثبّتها جوه مشروع واحد للـ team أو للـ cloud

استخدم الطريقة دي لو مساعد الـ AI شغال على نسخة من مشروعك على جهاز زميلك أو على الـ cloud، ومش شايف المهارات المتثبّتة على جهازك. لازم المشروع يكون ريبو git. نزّل AIDevWorkflow زي الخطوة 2، وبعدين شغّل الأمر ده من جوه الفولدر بتاعه:

سطر الأوامر
python3 skills/ai-dev-workflow/scripts/install.py install --project ../my-app
python3 skills/ai-dev-workflow/scripts/install.py doctor --project ../my-app

../my-app مثال لمشروع اسمه my-app جنب فولدر ai-dev-workflow. حط مكانه مسار فولدر مشروعك الحقيقي، ولو في مكان تاني، اكتب المسار كامل بين علامتين تنصيص. المثبّت بينسخ المهارة لـ .agents/skills/ai-dev-workflow و.claude/skills/ai-dev-workflow جوه المشروع. احفظ الفولدرين دول في git وارفعهم مع مشروعك، عشان الـ team ومساعدين الـ AI على الـ cloud يشوفوهم.

لو المهارة ظهرت مرتين جوه المشروع ده، يبقى فيه نسخة على جهازك ونسخة جوه المشروع. اختار طريقة واحدة للمشروع ده. وأمر doctor بيدوّر على النسخ المتكررة.

اختياري: سجّل قالب المواصفات بتاعك مرة واحدة

قالب المواصفات ملف .md فيه أقسام المواصفات فاضية، ومساعد الـ AI بيملاه لكل مهمة. لما تسجّله كقالب افتراضي، مساعد الـ AI بيقترحه لوحده في كل مشروع جديد، فمش هتحتاج تحدده كل مرة.

  1. جهّز الملف: انسخ examples/templates/example-spec-template.md لفولدر برّه أي ريبو، زي ../my-templates/spec.md، وعدّل أقسامه زي ما تحب.
  2. سجّله كقالب افتراضي من جوه فولدر ai-dev-workflow. my-template اسم إنت بتختاره:
    سطر الأوامر
    python3 skills/ai-dev-workflow/scripts/install.py add-template my-template ../my-templates/spec.md --default
  3. ملف القواعد (اختياري): ملف .json بيحدد المحرك يفحص إيه في المواصفات، زي الأقسام المطلوبة وشكل معايير القبول. لو عايزه، انسخ examples/templates/example-spec-template.rules.json لـ ../my-templates/spec.rules.json وعدّله على أقسام قالبك، وبعدين استخدم الأمر ده بدل أمر الخطوة 2:
    سطر الأوامر — مع ملف قواعد
    python3 skills/ai-dev-workflow/scripts/install.py add-template my-template ../my-templates/spec.md --rules ../my-templates/spec.rules.json --default

القالب بيتحفظ في مكتبتك الخاصة على جهازك، برّه كل المشاريع. لو عايز قالب تاني يبقى الافتراضي بعدين، استخدم install.py default-template وبعده اسمه. ولو ماسجّلتش قالب، مساعد الـ AI هيقولك ويسألك عن القالب، ومش هيعمل قالب من عنده.

تشغيل مهمة

من طلبك لحد نتيجة متراجعة. دورك في الخطوات اللي عليها علامة «أنت».

  1. سطر الأوامر

    افتح مساعد الـ AI جوه مشروعك

    روح لفولدر مشروعك، وشغّل مساعد الـ AI. ../my-app مثال، حط مكانه مسار مشروعك زي خطوة التثبيت:

    سطر الأوامر
    cd ../my-app
claude

    اكتب codex أو gemini بدل claude حسب مساعد الـ AI اللي بتستخدمه. ولو بتستخدم تطبيق desktop (زي Claude أو Codex أو Antigravity)، افتح فولدر المشروع في التطبيق بدل كده.

    لازم المشروع يكون ريبو git.

  2. محادثة مساعد AI

    ابدأ المهمة

    اكتب اسم المهارة وبعده طلبك. حط طلبك إنت مكان المثال، بالعربي أو بالإنجليزي:

    Claude Code، Gemini CLI، Antigravity
    /ai-dev-workflow ضيف المفضلة لقايمة المنتجات
    Codex
    $ai-dev-workflow ضيف المفضلة لقايمة المنتجات

    الطلب العادي من غير اسم المهارة مش بيشغّل الـ workflow.

  3. أنتمحادثة مساعد AI

    أول مرة في المشروع بس: أكّد الإعداد

    مساعد الـ AI بيفحص مشروعك ويقترح إعداد جاهز، وبيشرح كل اقتراح. وافق عليه زي ما هو، أو غيّر أي بند:

    • ملفات التعليمات اللي لقاها، زي CLAUDE.md أو AGENTS.md.
    • قالب المواصفات: قالبك الافتراضي لو سجّلته في مكتبتك، ولو لأ هيقولك ويسألك عن القالب.
    • الفحوص: بيطلّعها من ملفات مشروعك، زي flutter analyze وflutter test، ومعاها سطر بيشرح كل أمر. مش محتاج تكون عارفها قبلها.
    • حفظ سجلات المهام في git: بيشرح التلات اختيارات، وبيقولك أنهي فيهم أنسب لمشروعك:
      • all — كل السجلات في git: أي developer أو مساعد AI على جهاز تاني يقدر يكمّل المهمة، بس أي حد يوصل للريبو يقدر يقرا المواصفات والخطط.
      • config-only — الإعدادات بس في git: المهام على جهازك لوحده، فماينفعش تكمّلها من جهاز تاني، وتضيع لو الجهاز ضاع.
      • none — ولا حاجة في git: كله على جهازك لوحده.

    بترد مرة واحدة بس لكل مشروع، ونفس الإعدادات بتتستخدم في كل المهام اللي بعد كده.

  4. تلقائيأنت

    الاستكشاف: رد على أسئلة مساعد الـ AI

    مساعد الـ AI بيقرا الكود الأول، وبعدين بيسأل بس عن اللي الكود مش بيجاوب عليه. رد باختصار في الشات.

  5. أنتمحادثة مساعد AI

    لو تفاصيل الـ API ناقصة: ابعت الرسالة

    وافق على المواصفات

    المواصفات (spec) بتوصف هيتبني إيه قبل ما أي كود يتكتب. أقسامها بيحددها قالب مشروعك، وغالباً فيها:

    • الهدف: الميزة بتحل أنهي مشكلة، وإيه النتيجة المطلوبة.
    • المتطلبات: الميزة لازم تعمل إيه، وإيه اللي مش جزء منها.
    • الحالات الخاصة: زي النت يقطع أو القايمة تبقى فاضية.
    • القيود: إيه اللي ماينفعش يتغير.
    • معايير القبول: نعرف إزاي إن الشغل خلص.

    اقراها. لو صح، اكتب:

    ولو عايز تغيّر حاجة، اكتب عايز تغيّر إيه. الأسئلة أو «حلو، بس…» مش بتتحسب موافقة.

تغيير صغير؟ اكتب في الشات استخدم المسار السريع. مساعد الـ AI هيعرض المواصفات والخطة مع بعض، فتوافق عليهم في رسالة واحدة: موافق على المواصفات والخطة

الإيقاف والمتابعة وتغيير مساعد الـ AI

كل اللي في الجزء ده بيتكتب في شات مساعد الـ AI.

  • تكمّل مهمة بعدين محادثة مساعد AI

    اكتب اسم المهارة وبعده اسم المهمة (هنا الاسم المثال saved-favorites). مساعد الـ AI بيقولك اسم المهمة لما يعملها.

    Claude Code، Gemini CLI، Antigravity
    /ai-dev-workflow saved-favorites
    Codex
    $ai-dev-workflow saved-favorites
    قاعدة مهمة: كل مرة تفتح session جديدة عشان تكمّل مهمة بدأتها بـ AIDevWorkflow، نادي المهارة تاني باسم المهمة، حتى لو رجعت لنفس الشات القديم. في Claude Code، منع التعديل بدري مابيشتغلش غير بعد النداء ده.

    مثال: بتكمّل مهمة تاني يوم

    تخيّل المهارة مشرف على الشغل: لما تكتب /ai-dev-workflow بيحضر، فيتأكد إنك وافقت قبل أي كود، ويمنع التعديل بدري. بس بيمشي لما تقفل Claude. ولما تفتحه تاني، حتى في نفس الشات القديم، الكلام القديم بيفضل ظاهر قدامك، بس المشرف مش موجود.

    1. افتح Claude: شات جديد، أو نفس الشات القديم (claude --resume).
    2. أول رسالة تكتبها: نادي المهارة باسم المهمة.
      Claude Code
      /ai-dev-workflow saved-favorites
    3. بعد كده اكتب طلبك عادي، زي «كمّل».
    لو كتبت «كمّل» على طوللو ناديت المهارة الأول
    المشرفمش موجودرجع
    لو الـ agent حاول يكتب كود قبل موافقتكالكود بيتكتببيتمنع
    حالة المهمةبيكمّل من ذاكرة الشات، وممكن يغلطبيقرا ملفات المهمة ويكمّل من المكان الصح

    جربنا ده فعلاً: رجعنا لشات قديم وطلبنا تعديل في الكود من غير ما ننادي المهارة، فالتعديل عدّى. ولما نادينا المهارة الأول، نفس الطلب اترفض.

  • تكمّل في مساعد AI تاني محادثة مساعد AI

    افتح مساعد الـ AI التاني في نفس المشروع، واكتب نفس أمر المتابعة بالعلامة اللي بيستخدمها: / أو $. هيتأكد من كل موافقة تاني قبل ما يلمس الكود.

  • مراجعة من مساعد AI تاني محادثة مساعد AI

    بعد التنفيذ في مساعد AI، اطلب المراجعة من مساعد AI تاني:

    Claude Code، Gemini CLI، Antigravity
    /ai-dev-workflow audit saved-favorites
    Codex
    $ai-dev-workflow audit saved-favorites

  • توقّف المهمة مؤقتاً محادثة مساعد AI

    لو عايز تطلب حاجة مالهاش علاقة بالمهمة، اكتب الأول:

    ردّك:وقّف المهمة مؤقتاً

    المهمة الموقوفة مش بتقيّد مساعد الـ AI في أي حاجة، وتكمّلها بعدين باسمها.

  • تشوف كل المهام وكل واحدة في أنهي مرحلة محادثة مساعد AI

    Claude Code، Gemini CLI، Antigravity

    Codex

موافقتك وقواعد الأمان

  • كلامك إنت بس هو الموافقة.مساعد الـ AI بيسجّل ردك زي ما كتبته، زي «موافق على المواصفات»، وعمره ما بيوافق بالنيابة عنك.
  • اللي توافق عليه بيتجمّد.كل نسخة وافقت عليها بتتحفظ للقراية بس، ومعاها بصمة رقمية. ولو المستند اتغير بعدها، محتاج موافقتك من جديد.
  • مفيش كود قبل الموافقة على الخطة في المهمة الشغالة.في Claude Code فيه hook بيمنع تعديل الكود بدري. أدوات الـ AI التانية بتلتزم بالقاعدة، والمحرك بيكشف الملفات اللي اتغيرت قبل الموافقة.
  • فحص قبل كل session تعديل جوه الـ workflow.لما تبدأ session جديدة، أو تغيّر مساعد الـ AI، أو ترجع لمهمة، مساعد الـ AI بيتأكد من الموافقات تاني قبل ما يعدّل الكود في المهمة الشغالة.
  • لو إنت طلبت تتخطى مرحلة.مساعد الـ AI بيقول المراحل اللي طلبت تتخطاها، ويسجّل طلبك وسبب الإيقاف المؤقت، وبعدين ينفّذ طلبك برّه المهمة الشغالة. المراحل اللي اتخطت بتفضل مش مكتملة، ومش بتتسجّل موافقة إنت ماوافقتش عليها أو نتيجة ماتجربتش. ومساعد الـ AI عمره ما بيقرر يتخطى مرحلة من نفسه.
  • مفيش أسرار في السجلات.الباسوردات والـ tokens والمفاتيح عمرها ما بتتحفظ في ملفات المهمة.

لما معلومة تبقى ناقصة

مساعد الـ AI بيحدد المهمة دي محتاجة إيه بس، وبيصنّف كل حاجة:

مانع (Blocking)
لازم يبقى موجود قبل ما مرحلة تخلص: المواصفات أو الخطة أو التنفيذ أو الإنهاء.
مش مانع (Non-blocking)
مفيد، بس مش ضروري.
متأكَّد منه (Verified)
اتأكدنا منه بدليل موثوق.
مالوش علاقة (Not applicable)
مالوش دعوة بالمهمة دي.

لما الشغل يقف بسبب حاجة مانعة، رسالة الحالة بتبدأ بسطر زي ده (معناه: واقف مستني الـ contract بتاع الـ API):

BLOCKED — Awaiting backend API contract

ولما تفاصيل الـ API تبقى ناقصة، مساعد الـ AI بيكتب رسالة تبعتها زي ما هي، زي كده:

أهلاً! بنضيف ميزة المفضلة للأبلكيشن: المستخدم اللي عامل login بيدوس على القلب عشان يحفظ منتج، ويشوف المنتجات المحفوظة في شاشة المفضلة. عشان نكمّل المواصفات محتاجين: 1. إيه الـ endpoints بتاعة الحفظ والمسح وعرض القايمة؟ 2. القايمة متقسمة صفحات؟ ومترتبة إزاي؟ 3. الـ API بيرجّع إيه لو المنتج مابقاش موجود؟ ممكن تبعتلي مثال لـ request و response؟ شكراً!

الاختبار والمراجعة والحالة النهائية

  • أدلة حقيقية.المحرك بيشغّل كل فحص ويسجّل نتيجته مع بصمة للكود. ولو الكود اتغير بعدها، النتيجة بتبقى قديمة، ولازم الفحص يتشغّل تاني.
  • المشاكل القديمة لوحدها.المشاكل اللي كانت موجودة قبل المهمة بتتعرض لوحدها، بعيد عن المشاكل الجديدة.
  • الفحص اللي ماشتغلش عمره ما بيتحسب ناجح.بيتسجّل «واقف» ومعاه السبب.
  • مراجعة مستقلة.مساعد AI تاني أو session منفصلة بيراجع الشغل لو ينفع، ولو مش هينفع، التقرير بيقول إنها مراجعة تانية من نفس مساعد الـ AI.

AIDevWorkflow

Structured AI-Assisted Development — From Requirements to Release.

A skill for your AI coding tool. It runs only when you call it, taking your request to a tested, reviewed result after you approve the spec and plan. Each step is saved in your project so you or another AI tool can continue later.

Quick Start

The shortest path to your first task: install once on your computer, then use the skill inside your project.

Installation details and options

  1. Install the skill

    You need git and Python 3.9 or newer. Open Terminal (or PowerShell on Windows) and run these commands as they are. They download a folder named ai-dev-workflow into the folder Terminal is currently in, usually your home folder. Do not run them inside your project: this folder is a tool for your whole computer, and inside a project it can end up in the project's git by mistake. (To put the skill inside one project, use the project install option.) Keep that folder: you will need it to update. On Windows, use python instead of python3:

    Terminal / PowerShell
    git clone https://github.com/ahmedzein-dev/ai-dev-workflow.git
cd ai-dev-workflow
python3 skills/ai-dev-workflow/scripts/install.py
python3 skills/ai-dev-workflow/scripts/install.py doctor

    If the check ends with No problems found., close and reopen your AI tool.

  2. Open your project and start a task

    Open your project folder, which must be a git repository, in your AI tool. Type your request in its chat with the skill name. Use the form for your tool:

    Claude Code, Gemini CLI, Antigravity
    /ai-dev-workflow Add favorites to the product list
    Codex
    $ai-dev-workflow Add favorites to the product list

    Replace the favorites example with your own request.

  3. Confirm setup, then approve

    On the first task in a project, the AI tool proposes the spec template, project checks and how to save records, and explains each; accept them as they are or change what you want. It then shows the spec, followed by the plan. Read each and send the matching approval when it appears, if it is right:

    Two separate replies:approve the specapprove the plan

    After both approvals, the AI tool makes the change, runs the checks and reports the result.

Already installed? Start at step 2. For each decision and saved file, read the full task walkthrough.

Choose one method: install it on your computer for all projects (the steps below), or inside one project so teammates and cloud environments receive a copy.

    Terminal

    Download AIDevWorkflow

    Terminal

  3. Terminal

    Install the skill

    Terminal
    python3 skills/ai-dev-workflow/scripts/install.py

  4. Terminal

    Check the installation

    Terminal
    python3 skills/ai-dev-workflow/scripts/install.py doctor

    The last line should be: No problems found.

  5. You

    Restart your agent

    Close your agent and open it again, so it finds the skill.

Instead of a computer install: add the skill to one project

Choose this when a teammate or cloud AI tool only sees a checkout of your project. The project must be a git repository. Download AIDevWorkflow as in step 2, then run these commands from its folder:

Terminal / PowerShell
python3 skills/ai-dev-workflow/scripts/install.py install --project ../my-app
python3 skills/ai-dev-workflow/scripts/install.py doctor --project ../my-app

../my-app means a project named my-app next to your ai-dev-workflow folder. Replace it with your project's actual path; use a quoted full path if the project is elsewhere. The installer copies the skill into .agents/skills/ai-dev-workflow and .claude/skills/ai-dev-workflow inside that project. Commit and push both folders with the project so teammates and cloud AI tools can use them.

If the skill appears twice in this project, there is a computer copy and a project copy. Use one method for this project; doctor checks for duplicates.

Optional: register your own spec template once

A spec template is a .md file with the spec's sections left empty; the AI tool fills it in for each task. When you register it as your default, the AI tool proposes it automatically in every new project, so you don't choose it each time.

  1. Prepare the file: copy examples/templates/example-spec-template.md to a folder outside any repository, such as ../my-templates/spec.md, and adapt its sections.
  2. Register it as your default from the ai-dev-workflow folder. my-template is a name you choose:
    Terminal / PowerShell
    python3 skills/ai-dev-workflow/scripts/install.py add-template my-template ../my-templates/spec.md --default
  3. Rules file (optional): a .json file that tells the engine what to check in a spec, such as required sections and the format of acceptance criteria. If you want one, copy examples/templates/example-spec-template.rules.json to ../my-templates/spec.rules.json, edit it to match your sections, and run this command instead of the one in step 2:
    Terminal / PowerShell — with rules
    python3 skills/ai-dev-workflow/scripts/install.py add-template my-template ../my-templates/spec.md --rules ../my-templates/spec.rules.json --default

The template is kept in your private library on your computer, outside every project. To make another template the default later, use install.py default-template followed by its name. Without a registered template, the AI tool tells you so and asks you for one; it never invents one.

Run a task

From your request to a reviewed result. Your part is in the steps marked You.

  1. Terminal

    Open your agent in your project

    Go to your project's folder, then start your AI tool. ../my-app is an example; replace it with your project's path as in the installation step:

    Terminal
    cd ../my-app
claude

    Type codex or gemini instead of claude, depending on your agent. Using a desktop app (such as Claude, Codex or Antigravity)? Open the project folder in the app instead.

    The project must be a git repository.

  2. Agent chat

    Start the task

    Type the skill's name, then your request. Put your own request in place of the example:

    Claude Code, Gemini CLI, Antigravity
    /ai-dev-workflow Add saved favorites to the item list
    Codex
    $ai-dev-workflow Add saved favorites to the item list

    A request without the skill's name does not start the workflow.

  3. YouAgent chat

    First time in a project only: confirm the setup

    The agent inspects your project, proposes a ready setup and explains each item. Accept it as it is, or change any item:

    • Instruction files it found, such as CLAUDE.md or AGENTS.md.
    • Spec template: your default template if you registered one in your private library; otherwise it says so and asks you for one.
    • Checks: found from your project's own files, such as flutter analyze and flutter test, each with a one-line explanation. You don't need to know them in advance.
    • Saving task records in git: it explains the three options and recommends one for your project:
      • all — every record in git: any developer or AI agent on another computer can continue the task, but everyone with access to the repository can read the specs and plans.
      • config-only — only the settings in git: tasks stay on your computer, so they can't continue elsewhere and are lost with the computer.
      • none — nothing in git: everything stays on your computer.

    You answer once per project; every later task reuses these settings.

  4. AutomaticYou

    Discovery: answer the agent's questions

    The agent reads your code first, then asks only what the code cannot answer. Answer briefly in the chat.

  5. YouAgent chat

    If an API detail is missing: send the message

    The agent writes a ready message for your backend developer and stops. Send it the usual way (email, Slack…), then paste their reply into the chat.

  6. YouAgent chatApproval gate

    Approve the spec

    The spec describes what will be built, before any code is written. Its sections come from your project's template and usually include:

    • Goal: the problem the feature solves and the result wanted.
    • Requirements: what the feature must do, and what is out of scope.
    • Edge cases: such as no internet connection or an empty list.
    • Constraints: what must not change.
    • Acceptance criteria: how we know the work is done.

    Read it. If it is right, type:

    Your reply:approve the spec

    To change something, say what to change. Questions or "looks good, but…" do not count as approval.

  7. YouAgent chatApproval gate

    Approve the plan

    Read the implementation plan. If it is right, type:

    Your reply:approve the plan
  8. Automatic

    Implementation, tests, fixes and audit

    The agent changes the code step by step as planned, runs the project's checks, fixes what fails and reviews the result. You just wait.

    Your agent may still ask your permission to run a command or edit a file; that comes from the agent's own settings.

  9. You

    Read the final report

    A short summary: what was done, what was tested, what is still open. Its status is never higher than the evidence allows.

Small change? Type use the fast path in the chat. The agent shows the spec and the plan together, and you approve both in one message: approve the spec and the plan

Your approval and the safety rules

  • Only your words approve.The agent records your reply as you wrote it, such as "approve the spec". It never approves on your behalf.
  • What you approve is frozen.Each version you approve is saved read-only with a fingerprint. If the document changes later, it needs your approval again.
  • No code before an approved plan in an active task.In Claude Code, a hook blocks early code edits. Other agents follow the rule, and the engine reports files changed before approval.
  • A check before every editing session in the workflow.When a new session starts, the agent changes or a task resumes, the agent re-checks approvals before editing code under the active task.
  • If you explicitly ask to skip a stage.The agent names the skipped stages, records your request and the reason for pausing, then follows your instruction outside the active task. Skipped stages remain incomplete; no approval or test result is invented. The agent never decides to skip a stage on its own.
  • No secrets in records.Passwords, tokens and keys are never saved in task files.

When information is missing

The agent lists only what this task needs, and gives each item a class:

Blocking
Needed before a stage can finish: the spec, the plan, the implementation or completion.
Non-blocking
Helpful, not essential.
Verified
Confirmed with reliable evidence.
Not applicable
Not relevant to this task.

While a blocking item stops the work, the status message starts with a line like this:

BLOCKED — Awaiting backend API contract

For a missing API detail, the agent writes a message you can send as it is, for example:

Hi! We're adding saved favorites to the app: a signed-in user taps a heart to save an item and sees saved items on a favorites screen. To finish the spec we need: 1. Which endpoints save, remove and list favorites? 2. Is the list paginated, and how is it sorted? 3. What does the API return when the item no longer exists? Could you share an example request and response? Thanks!

Testing, audit and the final status

  • Real evidence.The engine runs each check and records its result with a fingerprint of the code. If the code changes later, the result is out of date and the check must run again.
  • Old problems stay separate.Problems that existed before the task are reported separately from new ones.
  • A check that did not run is never "passed".It is recorded as blocked, with the reason.
  • Independent review.Another agent or a separate session reviews the work when possible; otherwise the report says it was a second pass by the same agent.

The final status

StatusMeaning
CompletedEverything passed with evidence; no unresolved Critical or Important finding.
Completed with LimitationsNothing failed, but some items could not be verified, or you accepted an Important finding.
Partially CompletedSomething failed, steps remain, or a Critical finding remains, even if you accepted it.
BlockedWork cannot continue until someone provides what is missing.

Accepting a known Critical or Important finding never gives "Completed".

Questions, updating and uninstalling

Why doesn't the skill start by itself?

So that your normal requests stay normal. You decide when a task goes through the workflow.

Can I use my own spec template?

Yes. Each project uses the template you choose during setup. Rules you mark as mandatory block approval until they are met; recommendations only warn. There is no limit on how many requirements a spec has.

Does it need an internet connection?

The skill itself works offline. Your agent needs its usual connection.

Does it change anything in my project besides .ai-dev-workflow?

Only the code changes in plans you approved. Instruction files such as CLAUDE.md are never edited. Depending on how you chose to save records, a line may be added to .git/info/exclude.

Update to a newer version

From the folder where you downloaded ai-dev-workflow during setup, run these commands. Skip cd if you are already inside it:

Terminal
cd ai-dev-workflow
git pull
python3 skills/ai-dev-workflow/scripts/install.py update
Uninstall

From the folder where you downloaded ai-dev-workflow during setup, first see what would be removed. Skip cd if you are already inside it:

Terminal
cd ai-dev-workflow
python3 skills/ai-dev-workflow/scripts/install.py uninstall

Then remove it:

Terminal
python3 skills/ai-dev-workflow/scripts/install.py uninstall --yes

Task files in your projects are never touched.
